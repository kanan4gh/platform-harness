# 要求内容

## 概要

軽量パス宣言の判定をMarkdownの正規宣言行だけに限定し、例示・否定表現・説明文を宣言として誤認して `design.md` の欠落を見逃す問題を修正する。

- **関連Issue**: https://github.com/kanan4gh/platform-harness/issues/44
- **使用ハーネス**: Codex
- **軽量パス**: 適用
- **G3受け入れ**: 不要（lint本体と回帰テストのみの変更で、ハーネスのアダプタ構成・権限・フック・設定を変更しない）

## パス判定（通常パス・軽量パスのどちらでも必ず記載する。基準の正は add-feature 手順のステップ4）

- [x] 1. 既存パターンの踏襲のみで、新しいアーキテクチャ要素・新規依存を導入しない
- [x] 2. 変更対象が3ファイル以下(テスト除く)
- [x] 3. 対象文書の更新が不要
- [x] 4. データ形式・API契約の破壊的変更がない

**判定理由**:

- 基準1: **満たす**。`scripts/steering_lint.py` に既存の行単位正規表現と `strip_code_fences()` があり、その組み合わせを軽量パス宣言判定へ適用する。新規の層・抽象化・依存は導入しない
- 基準2: **満たす**。変更対象は `scripts/steering_lint.py` の1ファイル（テストを除く）
- 基準3: **満たす**。宣言形式とコードフェンスの扱いは既存のテンプレートおよび手順にすでに定義されており、今回はlint実装をその契約へ一致させる修正である。`AGENTS.md`、ハーネスアダプタ、永続ドキュメント、`docs/procedures/`、テンプレートの更新は不要
- 基準4: **満たす**。Markdown上の既定の宣言形式を厳密に検証する内部lint修正であり、データ形式・外部API契約を変更しない

4項目すべてを満たすため軽量パスを適用する。設計判断が発生しないため `design.md` は作成しない。

## 背景

`scripts/steering_lint.py` の `LIGHTWEIGHT_PATTERN` は行頭を固定せず、コードフェンスも除外しない。そのため、次の記述を軽量パス宣言として誤認する。

- コードフェンス内の例示
- `- **非軽量パス**: 適用` という否定表現
- `例として軽量パス: 適用` という説明文

誤認が起きると、実際には通常パスであるステアリングでも `design.md` の欠落がC1違反にならず、必須設計文書の欠落をローカル品質ゲートが見逃す。

## ユースケースの軸

**開発者がローカル品質ゲートを実行すると、正式な軽量パス宣言を持たないステアリングの `design.md` 欠落が、例示や類似表現に影響されずC1として検出される。**

## 実装対象の機能

### 1. 軽量パス宣言の厳密判定

- 宣言判定を行全体の正規形式 `- **軽量パス**: 適用` に限定する
- Markdownコードフェンス内を判定対象から除外する
- 既存の正常な軽量パス宣言による `design.md` 省略は維持する

### 2. 誤認ケースの回帰テスト

- 正規宣言が引き続き `design.md` 省略を許可することを確認する
- コードフェンス内の例示、否定表現、説明文では `design.md` 欠落がC1になることを確認する

## 受け入れ条件

### 宣言判定

- [ ] `- **軽量パス**: 適用` の実宣言だけが `design.md` 省略を許可する
- [ ] コードフェンス内の例示は軽量パス宣言として扱われない
- [ ] 否定表現と説明文は軽量パス宣言として扱われない

### テストと品質

- [ ] 正規宣言、コードフェンス内、否定表現、説明文を網羅する回帰テストがある
- [ ] 既存のsteering lintテストがすべて通る
- [ ] ローカル品質ゲートが全検査を通過する

## 成功指標

- Issue #44の3種の誤認ケースがすべてC1違反になる
- 正規宣言を持つ既存の軽量パスはC1違反にならない
- 誤認ケースのいずれかが再導入された場合、回帰テストが決定論的に失敗する

## スコープ外

以下はこのフェーズでは実装しない。

- 軽量パスの適用基準や宣言形式そのものの変更
- C1以外のsteering lint規則の変更
- Markdownパーサーや新規依存の導入
